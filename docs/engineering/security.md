## Invariants

1. PlatformOrganizationId and product tenant context are server-controlled.
2. One product cannot access another product’s operational database.
3. Product APIs enforce their own roles and permissions.
4. Subscription and feature checks are server-side.
5. Entitlement snapshots are signed/validated and time-bounded.
6. Posted financial records are append-only and corrected by reversal/adjustment.
7. HealthCare patient self-scope remains HealthCare-specific.
8. Secrets and tokens never appear in logs.
9. Localization cannot expose untranslated internal keys or sensitive debug details.
10. Theme selection cannot weaken focus visibility or contrast.
11. Clinical PHI must not flow into Platform audit or entitlement payloads.
12. SaaS subscription payments are distinct from POS retail sale payments and from POS customer-credit payments.
13. POS MVP GCash is manually recorded; do not store GCash credentials, PINs, OTPs, or access tokens. Platform SaaS GCash (if added later) uses Platform payment entities only.
14. **P2-WP02:** Platform User is not Patient/Customer; Platform Organization is not Clinic/Store; organization membership roles are not product-local roles; no credentials in domain models; user suspension and membership suspension are separate.
15. **P2-WP03:** Commercial entitlements are not operational settings; snapshots must not contain clinical/retail records; published plan versions are immutable; SaaS payments are not modeled in this foundation.
16. **P2-WP04:** Outbound contracts exclude credentials and clinical payloads; unsupported contract majors fail closed; Platform organization roles must not be treated as clinical roles; contracts ≠ completed HealthCare integration.
17. **P2-WP05:** Migration dry-run models exclude credentials/PHI; sensitive metadata probe fails closed; dry-run ≠ production migration; rollback evidence required before cutover (R-027/R-044).
18. **P3-WP01/P3-WP02:** Catalog, organization, and subscription APIs are unauthenticated (development-stage only). Do not expose publicly without Platform authentication. Persistence exceptions must not leak provider details. Commercial `ActivateSubscription` does **not** collect or verify payment.
19. **P3-WP03:** Manual SaaS payment APIs are unauthenticated. Actor references (`confirmedBy`, `rejectedBy`, `voidedBy`) accept plain strings — **production blocker** requiring authenticated Platform operator with payment-confirm permission. No payment credentials, GCash PINs, OTPs, card data, or gateway tokens stored. Manual GCash means an operator confirms externally and records the reference; Platform does not call GCash API, generate QR, or receive webhooks.
20. **P3-WP04/P3-WP05:** Entitlement snapshot and feature-override APIs are unauthenticated. Snapshots must not contain clinical/retail operational data. Overrides require reason and actor GUID (no auth yet — production blocker). Provisional 24h refresh policy is **not** a final R-022 decision. Snapshots are not product delivery. Phase 3 is closed with these limitations explicit.
21. **P4-WP01:** Platform Admin UI is unauthenticated and must display a development-stage security warning. Dev operator context is a display label only — not authorization. Admin must not call Infrastructure/EF directly. Manual-payment and entitlement-delivery warnings are mandatory on those screens. Do not describe Admin as production-secure.
22. **P4-WP02:** Platform user/membership/product-access APIs remain unauthenticated. Product-access assignment is commercial entry eligibility only — never product-local roles. Suspended/disabled users and ineligible subscriptions fail closed. No passwords, JWT, MFA, SSO, or AspNet Identity tables in this work package.
23. **P4-WP03:** Subscription and manual SaaS payment Admin mutations remain without production authentication. Manual confirmation is not provider verification. No card numbers, CVV, PIN, OTP, gateway SDKs, webhooks, or invoice engines. Subscription changes do not deliver entitlements or assign product-local roles.
24. **P4-WP04:** Sensitive Platform mutations enforce server-side `PlatformAuthz` (fail closed → 403 + denied audit). Append-only `platform.audit_records` must never store passwords, tokens, card/GCash secrets, PHI, raw payloads, or exception dumps. Admin UI permission visibility is not authorization. DevelopmentOperator full access is Development/Testing-only and is not production authentication. Themes must preserve focus/contrast; localization must not leak keys or sensitive debug text.
25. **P6-WP01:** POS customer APIs are organization-scoped via `X-Pos-Organization-Id` and fail closed (404) across organizations. Development-stage only — not production authentication. Customer notes must not be treated as credit records. No PHI. Separate POS database must not contain Platform/HealthCare tables or cross-database FKs.
26. **P6-WP02:** Remarks-based credit entries are organization-scoped the same way. Append-only after create; corrections use explicit reversal with a required reason. Outstanding is derived (updated in P6-WP03 to credits − repayments). SaaS subscription payments remain distinct from customer Utang credit.
27. **P6-WP03:** Repayments are organization-scoped; actor captured via Development/Testing `X-Dev-Platform-User-Id`. Overpayment is rejected in a serializable transaction. Unified ledger is read-only. Statements and receipts remain later.
28. **P6-WP04:** Credit due dates and overdue queries are organization-scoped; set/clear require Development/Testing `X-Dev-Platform-User-Id`. Due-date history is append-only. FIFO aging is derived (not persisted). Effective business date is server UTC calendar day only — org timezone not defined.
29. **P6-WP05:** Statements and receipts are organization-scoped projections (no new persistence). Commercial gates use Development-stage `X-Pos-Subscription-Status` / `X-Pos-Feature-Grants` — **not production-secure**. Product entry vs feature authorization are separate; Suspended denies; PastDue/Cancelled/Expired continuity only. OD-07/08/09 resolved.
30. **P7-WP01:** DeviceId is SecureStorage-only and never authorization proof. Foundation SQLite holds schema/context metadata only (no tokens, entitlements, customers, or financial rows). Protected POS shell requires online access validation — no offline grace window. SQLCipher deferred until business-data offline WP. Diagnostics blocked outside Development/Testing.
31. **P7-WP02:** Offline payloads are AES-GCM encrypted; encryption key is SecureStorage-only. Queue never logs plaintext/tokens. Server idempotency never bypasses authorization or business invariants. Pending work is retained across logout/access loss (OD-10) and never silently deleted. Dev offline probe is Development/Testing-only.
32. **P7-WP03:** Local customer/credit business cache uses row-level AES-GCM via the same SecureStorage-backed `pos.local.payload.key`; no plaintext mobile, address, notes, remarks, or amounts in SQLite. SQLCipher deferred (R-129). Offline mutations require same in-process session after online auth — no time-based entitlement grace (R-022). Key loss fails closed; never log decrypted business data.
33. **P7-WP04:** Local repayment projections and due-date pending fields use the same row-level AES-GCM protector; no plaintext repayment amount/remarks in SQLite text columns. Schema v4 adds `local_repayment_projection` only — no local `repayments` table mirroring server SoR. Local overpayment rejected (`local_overpayment`). Reversal/due-date require server-confirmed source entries. Duplicate pending reversal blocked. Offline statements/receipts not enqueued. Same session gate and R-022/R-129/OD-10 limitations as P7-WP03.
34. **P7-WP05:** Closeout hardened capability revalidation before dispatch, Recovery Required sync state (including key loss), encrypted pending due-date/reversal reasons, and safe conflict JSON. Full-database encryption still deferred — **required production gate**. Local DB existence never grants access. Diagnostics remain Development/Testing-only.
35. **P8-WP01:** Catalog APIs are organization-scoped via `X-Pos-Organization-Id` and gated by Development-stage `store-catalog-view` / `store-catalog-manage` grants — **not production-secure**. Continuity (PastDue/Cancelled/Expired) allows view only when granted; mutations require manage + Trialing/Active/GracePeriod. Suspended/missing/stale/unknown deny. Online-only — no offline catalog cache or queued mutations. No stock/sales exposure.
36. **P8-WP02:** Sales APIs are organization-scoped and gated by `store-sales-view` / `store-sales-create` / `store-sales-void`. Continuity allows view only; create/void require full commercial state. Checkout totals are server-authoritative; ManualGCash is never gateway-verified. Actor via Development-stage `X-Dev-Platform-User-Id`. Online-only cart/checkout — no offline sale queue. No inventory deduction.
37. **P8-WP03:** Product-Based Utang checkout requires `store-sales-create` **and** `customer-credit-create`. Void requires `store-sales-void` **and** `ReverseCredit` (`customer-credit-view`). Linked credit reverse is blocked standalone (`pos.credit_entry.reversal.requires_sale_void`). Totals/debt are server-authoritative; online-only. No inventory deduction.
38. **P8-WP04:** Inventory APIs gated by `store-inventory-view` / `store-inventory-manage`. Continuity view-only; manage requires full commercial state. Sale stock deduction/restoration runs under sales capabilities (not a bypassable client inventory grant). On-hand cannot go negative. Online-only — no offline stock.
39. **P8-WP05:** Expense APIs gated by `store-expenses-view` / `store-expenses-manage`. Continuity view-only; create/void/category manage require full commercial state. ManualGCash is never gateway-verified. Online-only — no offline expense queue.
40. **P8-WP06:** Dashboard/reports gated by `store-dashboard-view` / `store-reports-view`. Continuity/read through PastDue/Cancelled/Expired when granted; Suspended deny. Online-only authoritative totals.
41. **P8-WP07:** Phase 8 closeout consolidates the full `store-*` matrix (view/manage + dashboard/reports), proves fail-closed Suspended/missing/stale/unknown, dual Utang sale+credit gates, and Platform↔POS feature-code parity. Headers remain Development/Testing-only — **not production-secure**. Online-only Basic Store unchanged.
42. **P9-WP01:** Production rejects Development/Testing org/actor headers (`pos.development_headers.unavailable`) and ignores commercial headers (Unknown fail-closed). Platform ignores `X-Dev-Platform-User-Id` outside Dev/Testing. Production startup fails closed on missing DB config, known-dev password, or wildcard AllowedHosts. CORS deny-by-default; partitioned rate limits; safe exception ProblemDetails; security headers; HTTPS when `Security:EnforceHttps`. Base appsettings connection strings empty. **Not production authentication (R-091).** R-129 / full-DB encryption and R-109 remain open.
43. **P13-WP01:** Authoritative production authentication architecture and threat model recorded. Locked chain Platform User → Organization Membership → Product Access → Product-Local Role. Target: Admin cookie/server session; API/MAUI Platform bearer tokens; local password MVP; MFA readiness only; Dev headers never Production auth. **No auth code in P13-WP01.** R-091 remains open.
44. **P13-WP02:** Platform credential persistence (`platform_user_credentials`), ASP.NET Core `PasswordHasher<TUser>` (versioned PBKDF2, salt, work factor, constant-time verify, rehash-needed), lockout/email-verified flags, hardened first-admin bootstrap (disabled by default; shared secret; Production forbid; rate limit; concurrency-safe), credential APIs and audit actions without secrets. **No login cookies/tokens.** R-091 remains open.
45. **P13-WP03:** Browser login/logout, `platform_auth_sessions`, HttpOnly session cookie + session header, sliding/absolute expiry, stamp invalidation, trusted session actor, Admin `/admin/login` (Production-required), auth audit events, login rate limit. **No bearer tokens / MFA / password-reset delivery.** R-091 remains open.
46. **P13-WP04:** Authenticated password change; forgot/reset with hashed one-time tokens (`platform_credential_tokens`); email-verification token workflow with no-vendor delivery boundary; lockout audit + unlock; session revoke after sensitive changes; Admin change/forgot/reset + Users credential panel. R-091 remains open.
47. **P13-WP05:** Trusted session organization context from active memberships (`selected_organization_id` on `platform_auth_sessions`); none/one/many selection; select/switch APIs; stale context cleared on membership/org changes; Admin header switcher; actor org claim from session only. R-091 remains open.
48. **P13-WP06:** Platform opaque Bearer access tokens (`platform_access_tokens`); Admin session product-entry; MAUI password+Bearer; POS introspect middleware + product-local roles; Dev headers remain Dev/Testing-only. R-091 remains open.
49. **P13-WP07:** MFA readiness contracts (`PlatformMfaOptions`, null factor store, readiness DTO signals on login/me/token/introspect); no enrollment/challenge; Production forbids MFA flags; suspend/deactivate revoke sessions+tokens; token-ops + email-verification rate limits; Admin/POS HTTPS BaseUrl guards; access-token lifetime clamp. R-091 remains open.
50. **P13-WP08:** Google/Facebook external authentication (`platform_external_logins`); create/link Platform User; browser session; Admin login buttons; Dev/Testing simulation endpoint; never auto-grants admin/membership/entitlement/product roles.
51. **P13-WP09:** Phase 13 closeout; optional verified recovery email (credential-token purpose; skip allowed; recovery-only); **R-091 closed for Phase 13 scope** with residuals (MFA enforcement, email vendor, enterprise SSO/AD beyond Google/Facebook). Portfolio remains not Production-ready.
